# 04. UART1 / UART2 / UART0-AUX

Три одинаковые страницы, по одной на канал. Каждая состоит из двух карточек:
параметры порта и сеть канала.

## Параметры порта

| Поле | Что означает |
|---|---|
| **Ім’я каналу** | подпись в интерфейсе и в журнале |
| **Увімкнено** | поднимать ли канал. Выключенный UART не запускается, но **UDP-порт за собой держит** |
| **RX GPIO**, **TX GPIO** | выводы. В однопроводном режиме поле одно — «CRSF GPIO (один провід)» |
| **Швидкість, бод** | 9600…5000000 |
| **Біт даних**, **Парність**, **Стоп-біти** | формат кадра. Для CRSF — 8N1 |
| **Інверсія RX**, **Інверсія TX** | аппаратная инверсия сигнала |
| **Режим CRSF** | см. ниже. Появляется, когда протокол канала — CRSF |
| **Дуплекс** | для CRSF задаётся режимом и недоступен для правки |
| **RS-485 DE GPIO**, **RS-485 /RE GPIO** | вывод управления направлением трансивера. `-1` — не используется. Никогда не подключайте линию RS-485 к GPIO напрямую: нужен трансивер |
| **RX watchdog, мс** | нет данных дольше — канал считается потерянным. `0` выключает |

> Не используйте выводы **0, 16, 18, 19, 21, 22, 23, 25, 26, 27** — они заняты
> Ethernet, и плата потеряет сеть. **1 и 3** — консоль. **34–39** — только
> вход, передавать через них нельзя.

## Режим CRSF

Их три, и они описывают **физически разные схемы**. Режим задаёт и дуплекс, и
назначение выводов; отдельно менять дуплекс нельзя — прошивка отклонит.

### RX-only TX16S S.Port

Пульт отдаёт CRSF по S.Port, плата только слушает. Провод один, но
двунаправленным он **не является**: TX платы никуда не подключён.

```
TX16S S.Port ──────► RX GPIO
GND ────────────────  GND
```

Мост работает строго в одну сторону, UART → сеть. Типовое: RX GPIO33, 400000,
8N1, инверсия RX включена.

**Передача в этом режиме запрещена на уровне кода.** Попытки записи считаются
как «Заблоковано передач» и в провод не попадают. Это не осторожность: запись
в линию S.Port работающего TX16S вешала пульт повторяемо.

### Single-wire CRSF

Настоящая общая двунаправленная линия: обе стороны говорят по очереди.

```
CRSF signal ────────  один GPIO (RX и TX — один и тот же)
GND ────────────────  GND
```

RX GPIO и TX GPIO **обязаны совпадать**. Нужна подтяжка к 3.3 В — внешняя
1–4.7 кОм надёжнее внутренних ~45 кОм. Общий GND обязателен.

Приём здесь слышит собственный передатчик. Мост снимает своё эхо сам, двумя
независимыми рубежами, и настраивать для этого ничего не нужно.

### Full-duplex CRSF

Два отдельных провода.

```
TX устройства ──────► RX GPIO
RX устройства ◄────── TX GPIO
GND ────────────────  GND
```

RX GPIO и TX GPIO **обязаны различаться**. Исчезают разом арбитраж линии,
ожидание промежутка, эхо и коллизии — ценой одного лишнего вывода.

### Какой выбирать

Решает **плотность потока**, а не удобство. Поток управления CRSF — 250 кадров
в секунду, это 16% времени линии, но промежутки идут кусками по 3.3 мс, и
встречный кадр должен попасть внутрь одного из них.

Измерено на одном и том же устройстве:

| | один провод | два провода |
|---|---|---|
| принято телеметрии | 1 кадр за 60 с | 13 кадров/с |

Телеметрия не терялась — ей негде было пройти. Поэтому: **двусторонний обмен с
плотным потоком в одну сторону — только два провода.** Один берут, когда так
устроено само устройство.

## Вихід на спільному дроті

Видно только в однопроводном режиме. Две настройки электрики вывода.

| Настройка | Значения | Что делает |
|---|---|---|
| Тип выхода | открытый сток / двухтактный | чем формируется уровень |
| Подтяжка | вверх / вниз / нет | куда тянуть вывод в покое |

**Открытый сток** умеет тянуть линию только вниз; единицу формирует подтяжка.
Если оба конца заговорят разом, они лишь совместно потянут линию вниз, а не
замкнут выходы друг друга.

**Двухтактный** формирует оба фронта сам. Полезен, когда фронт вверх не
успевает, но при одновременной передаче выходы будут бороться.

**Подтяжка должна совпадать с уровнем покоя линии**, иначе она воюет с ней
постоянно.

Замер на линии пульта TX16S, 40 секунд на комбинацию:

| Конфигурация | приём | ошибок CRC | эхо искажено |
|---|---|---|---|
| **открытый сток + вверх** | 250/с | **16** | 48% |
| открытый сток, без подтяжки | 264/с | 2518 | 97% |
| двухтактный + вверх | 249/с | 45 | 47% |
| двухтактный, без подтяжки | 263/с | 3094 | 78% |

Выводы: **подтяжка обязательна** — без неё ошибки CRC растут в полтораста раз.
Тип выхода на этой линии не значит ничего. Другому железу может подойти иное —
для того настройка и вынесена.

## Черга на передачу и Такт і очікування

Шесть параметров арбитража общего провода. **Пустое поле — значение по
умолчанию, оно показано серым внутри поля** и приходит от прошивки.

| Поле | По умолчанию | Откуда число |
|---|---|---|
| кадров в очереди | 6 | ~24 мс потока RC при 250 Гц |
| срок годности, мс | 40 | 10 периодов RC |
| пауза между посылками, мкс | 2500 | ровный такт вместо залпа |
| ожидание при молчащей линии, мс | 2 | граница задержки, когда встречный конец молчит |
| таймаут «линия замолчала», символов | 23 | заметно меньше промежутка 3.35 мс |
| окно узнавания эха, мс | 60 | дольше эхо на проводе не живёт |

> **Глубина очереди и срок годности — это приоритет свежести над
> сохранностью.** Для управления устаревший кадр вреднее потерянного: он
> описывает положение стика, которого уже нет. Увеличив их, вы получите не
> «меньше потерь», а задержку. Поднимать осмысленно там, где в провод идёт
> телеметрия, а не управление.

## Сеть канала

| Поле | Что означает |
|---|---|
| **Мережевий режим** | выключено, UDP, TCP server, UDP + TCP server |
| **UDP listen порт** | на каком порту канал принимает |
| **TCP server порт**, **Макс. TCP клієнтів** | для режимов с TCP |
| **Приймати з будь-якої IP** | снятая — принимать только с доверенного адреса |

> **Порты не должны совпадать между каналами.** Проверка это отклонит, но
> помнить стоит: выключенный UART свой порт не освобождает.

### UDP destinations

До четырёх адресатов, каждый со своей галочкой. Порядок отправки:

1. все **включённые** адресаты с заданными адресом и портом;
2. если таких нет — **выученный пир**, источник последней входящей датаграммы;
3. если нет ни того ни другого — отправка не выполняется и считается в
   «Нікуди відправляти».

Адресат с пустым адресом или нулевым портом не считается настроенным, даже с
галочкой.

> **Для одностороннего потока адресат обязателен.** Приёмник CRSF на ПК часто
> только слушает: он никогда не пишет на плату, поэтому выучить его неоткуда, и
> схема «отвечаем туда, откуда пришло» для него не работает вовсе.
