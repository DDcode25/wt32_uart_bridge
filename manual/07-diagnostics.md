# 07. Diagnostics

Пять карточек: подробности по каналам, управление журналом, дамп трафика, сам
журнал и список API.

---

# Діагностика каналів

Карточка на каждый канал. Ниже — **каждое поле** и что оно означает.

## Как канал подключён

| Поле | Значение |
|---|---|
| **Протокол** | что разбирает канал: RAW, CRSF, S.Bus, MAVLink |
| **Режим CRSF** | `RX-only TX16S S.Port`, `Single-wire CRSF` или `Full-duplex CRSF`. У режима RX-only рядом стоит пометка, что мост работает только в сторону сети |
| **Дріт** | выводы, скорость, дуплекс. В однопроводном режиме показан один GPIO вместо пары |
| **Інверсія** | для общего провода — одна на линию, для двух проводов — раздельно по направлениям |

## Байты и общие счётчики

| Поле | Что означает | Когда тревожно |
|---|---|---|
| **RX / TX байт** | всего прошло через канал с момента запуска | RX не растёт — с провода ничего не идёт |
| **UART overruns** | приёмный буфер драйвера переполнялся: не успели забрать данные | любое ненулевое значение, растущее со временем |
| **Відкинуто на передачу** | байты, выброшенные при переполнении очереди передачи | растёт — провод медленнее источника |
| **Заблоковано передач** | попытки записать в канал, которому передавать запрещено (режим RX-only) | растёт — маршрутизация шлёт туда, куда нельзя. Не ошибка транспорта, а неверная настройка |
| **Останнє приймання UART** | время последнего приёма, мс от старта | стоит на месте — приём прекратился |
| **Watchdog** | `OK` или `таймаут` — данных не было дольше заданного в настройках порта | `таймаут` при живом источнике — проверьте выводы и скорость |

## Сеть канала

| Поле | Что означает | Когда тревожно |
|---|---|---|
| **UDP пакетів rx/tx** | принято и отправлено датаграмм | tx не растёт при растущих кадрах — некуда слать |
| **UDP слухач** | `піднято` — сокет открыт. `не піднято — порт зайнятий` — совпадение портов у двух каналов | помните: **выключенный UART свой порт не освобождает** |
| **Адресати UDP** | куда реально уходит поток, списком. `явних немає` — работает выученный пир | |
| **Вивчений пір** | адрес источника последней входящей датаграммы | `ще не було вхідних пакетів` при одностороннем потоке — норма, но тогда нужен явный адресат |
| **Нікуди відправляти** | отправить было что, а некуда: ни включённого адресата, ни пира | **любое ненулевое — незаконченная настройка.** Слушающий приёмник сам не пишет, выучить его неоткуда |
| **UDP відкинуто** | датаграммы, отброшенные фильтром источника | растёт — приходит с адреса, которому не доверяем |
| **TCP байт rx/tx**, **TCP клієнтів** | для режимов с TCP-сервером | |

## CRSF: поток с провода

| Поле | Что означает | Когда тревожно |
|---|---|---|
| **CRSF кадрів** | целых кадров, прошедших длину и CRC | не растёт при растущих байтах — промах по скорости или полярности |
| **CRSF кадрів каналів** | из них кадров `0x16` RC_CHANNELS_PACKED | |
| **Помилок CRC** | кадр собрался, но контрольная сумма не сошлась | **главный показатель качества линии** |
| **Помилок синхронізації** | байты, отброшенные при поиске начала кадра | см. врезку ниже — сам по себе не показатель |
| **Некоректна довжина** | адрес нашёлся, а длина недопустима | растёт вместе с CRC — линия шумит |
| **Failsafe** | флаг из кадра каналов | |
| **Uplink LQ / RSSI / SNR** | качество радиолинка, как его сообщает устройство | LQ падает — проблема в эфире, а не в проводе |
| **Типи кадрів** | разрез по типам: `Канали`, `Link stats`, `Батарея`, `GPS`, `Attitude`, `Режим`, `Ping`, `Device info`, `MSP` | показывает, что реально идёт по линии |
| **Останній тип** | тип последнего принятого кадра | |

> **Ошибки синхронизации — не показатель здоровья.** На однопроводном CRSF они
> растут примерно на единицу с каждым кадром: в потоке идёт лишний байт между
> кадрами, и разбор отбрасывает его при поиске начала. Судить о линии надо по
> **ошибкам CRC и темпу кадров**. Ориентир исправной связки: ~6850 Б/с,
> ~250 кадров/с.

## Спільний провід

Блок появляется **только в однопроводном режиме** — у полного дуплекса его нет,
потому что там нечего арбитрировать и эха не бывает физически.

### Состояние и объёмы

| Поле | Что означает |
|---|---|
| **стан** | `RX_LISTEN` — вывод работает входом, слушаем. `RX_FRAME` — идёт приём. `TX_FRAME` — передаём, вывод отдан UART. `RETURN_TO_RX` — дожидаемся ухода последнего стоп-бита |
| **Кадрів провід rx/tx** | принято чужих целых кадров и отдано своих |
| **Байт провід rx/tx** | то же в байтах, включая то, что не сложилось в кадры |
| **Помилок CRC**, **Некоректна довжина**, **Помилок синхронізації** | те же ошибки, но у внутреннего разбора сервиса провода |
| **Переповнень приймача** | `UART_FIFO_OVF` и `UART_BUFFER_FULL`: данные с провода терялись, не успели забрать |

### Очередь и причины отказа передачи

| Поле | Что означает | Что делать |
|---|---|---|
| **Черга на передачу** | сейчас / максимум за сессию, в скобках ёмкость и срок годности | постоянно упирается в ёмкость — провод не успевает |
| **Відкинуто: застаріло** | кадр пролежал дольше срока годности | линия занята встречным потоком; для управления это правильное поведение |
| **Відкинуто: переповнення** | вытеснен самый старый, чтобы принять свежий | провод медленнее источника |
| **Відкинуто: не пройшло перевірку** | из сети пришло то, что не сошлось по длине или CRC | в шину такое не отдаём; растёт — источник за сетью портит кадры |
| **Немає вікна для передачі** | момент был занят чужой передачей, кадр остался ждать | норма в разумных количествах: так и работает арбитраж |
| **Помилок передачі UART** | драйвер отдал не всё, что просили | |

### Эхо и линия

| Поле | Что означает |
|---|---|
| **Ехо знято / спотворено** | своё эхо, узнанное целиком и вернувшееся неузнаваемым |
| **Розворотів лінії rx→tx / tx→rx** | сколько раз вывод менял направление. Должны совпадать между собой |
| **Лінію утримано понад норму** | вывод отпущен позже расчётного времени посылки. На общем проводе это гарантированно убитый встречный кадр |
| **Відповідей на опит пристроїв** | сколько раз мост ответил на `0x28` кадром `0x29`. Пока пульт не получит ответ, он не считает мост модулем и шлёт опрос вместо кадров управления |
| **Найдовший розбір пачки** | сколько заняла обработка принятого, мкс |

> **Растущее «Ехо знято» — норма, а не отказ.** На общем проводе приёмник
> физически слышит собственный передатчик, и мост эти кадры отбрасывает, чтобы
> они не ушли обратно в сеть. Счётчик показывает, что защита работает.
>
> Тревожен другой — **«спотворено»**, растущий сопоставимо с числом посылок:
> он означает, что своя же посылка возвращается неузнаваемой.
>
> **«Найдовший розбір пачки»** стоит сверять с межкадровым промежутком. При
> CRSF 400000 бод и 250 кадрах/с промежуток 3.35 мс. Если разбор занимает
> больше, к моменту передачи встречная сторона уже начала следующий кадр, и мы
> бьём прямо в него.

## Потік із мережі

Что пришло с той стороны моста и ушло в провод.

| Поле | Что означает |
|---|---|
| **Кадрів / CRC** | целых кадров из сети и ошибок среди них |
| **З них кадрів каналів** | сколько из них `0x16` |
| **Останній тип**, **Типи кадрів** | разрез по типам |
| **Downlink LQ / RSSI / SNR** | обратный канал радиолинка |
| **TX power / RF mode / антена** | из кадра link statistics |
| **Батарея** | напряжение, ток, израсходовано мА·ч, остаток в процентах |
| **GPS**, **GPS швидк. / курс / висота**, **Супутників** | из кадра GPS |
| **Attitude pitch/roll/yaw** | углы, в градусах |
| **Режим польоту** | строка из кадра `0x21` |
| **Утримання (повторів)** | сколько раз провал в телеметрии закрывался повтором последнего кадра link statistics |
| **Брак із мережі** | байты, не сложившиеся в целый кадр и потому **не отданные в провод** |

> Пустые поля с прочерком означают, что кадр такого типа не приходил ни разу —
> это отличается от «пришёл и в нём ноль».
>
> **Утримання**, растущее при живом источнике, означает, что он отдаёт кадры
> неровно. **Брак із мережі** растёт — источник режет кадры по датаграммам или
> они теряются по дороге.

## S.Bus

| Поле | Что означает |
|---|---|
| **S.Bus кадрів** | целых кадров |
| **Помилок кадру** | не сошлись стартовый или конечный байт |
| **Failsafe**, **Frame lost** | флаги из кадра |
| **CH17 / CH18** | два дискретных канала |

## MAVLink

| Поле | Что означает |
|---|---|
| **MAVLink v1 / v2** | кадров каждой версии |
| **Помилок кадру** | структурные ошибки. `CRC_EXTRA` не проверяется, на транзит это не влияет |
| **Heartbeat** | сколько heartbeat принято. Появились — связь с контроллером есть |
| **sysid / compid** | из последнего кадра |
| **Останній msgid** | номер последнего сообщения |

## RAW

**RAW байтів усього** — всё, что прошло насквозь. Разбора в этом режиме нет.

# Журналювання

**Детальний журнал** — поднимает порог с WARN до INFO и включает сводку раз в
30 секунд.

На задержку каналов в установившемся режиме практически не влияет: в путях
приёма и передачи журналирования нет вовсе. Заметен он только пока UART0
остаётся консолью — тогда каждая строка блокирует задачу на время передачи по
проводу, около 8 мс на 115200.

Нагружает канал не он, а дамп трафика.

---

# Дамп трафіку

Побайтовый вывод в журнал, галочка на канал.

**В NVS не сохраняется**: после перезагрузки всегда выключен, и кнопка
«Зберегти» на него не влияет. Забытый включённым иначе молча грузил бы журнал.

Строки помечены направлением — на общем проводе это существенно, потому что
четыре разные вещи выглядят в hex одинаково:

| Метка | Что это |
|---|---|
| `UART RX` | пришло с провода |
| `UART TX` | отдано в провод |
| `UDP RX` | пришло из сети |
| `echo suppressed` | снято как собственное эхо |

Исправный транзит виден как совпадение пары байт в байт:

```
UART1_CRSF UDP RX  26B: ee 18 16 11 f4 61 2b a0 ...
UART1_CRSF UART TX 26B: ee 18 16 11 f4 61 2b a0 ...
UART1_CRSF UART RX 14B: c8 0c 14 11 11 64 b6 00 00 00 23 64 c8 16
```

Последняя строка — настоящий кадр link statistics со встречной стороны.

**Прореживание:** не чаще строки в 100 мс на каждое направление, до 32 байт в
строке. CRSF на 400000 бод забил бы кольцевой буфер за секунду. Пропущенное
считается и печатается в следующей строке: `[пропущено 25 порцій / 650 Б]`.

> На однопроводном канале в дамп попадают только **целые кадры**. Мусор, не
> сложившийся в кадр, так увидеть нельзя — для этого есть приём с RAW-режимом,
> см. [09. Как диагностировать](09-diagnostika.md).

# Журнал пристрою

Кольцевой буфер сообщений прошивки, он же `GET /api/log`.

Нужен потому, что **UART0 может быть отдан каналу данных**. У ESP32 три
UART-периферии, все три заняты каналами, а UART0 — ещё и консоль. Как только
канал забирает UART0, консоль замолкает: иначе строки журнала физически
подмешались бы в поток канала и уехали клиенту по сети.

**Начало журнала закреплено** и не вытесняется: старт каналов, передача UART0,
получение адреса. Дальше идут свежие записи. Загрузочная часть, включая пароль
первого запуска, печатается **до** перехвата — её видно в терминале при первом
включении, но в этом буфере её нет.

# API пристрою

| Метод | Точка | Что делает |
|---|---|---|
| GET | `/` | этот интерфейс |
| GET | `/api/status` | снимок состояния: система, Ethernet, каналы, счётчики |
| GET | `/api/log` | журнал |
| GET | `/api/config` | текущая конфигурация |
| POST | `/api/config` | записать конфигурацию, тело — тот же JSON, что отдаёт GET |
| POST | `/api/profile` | `{"profile":1}` |
| POST | `/api/password` | `{"password":"…"}`, минимум 8 символов |
| POST | `/api/reboot` | перезагрузка, тело не нужно |
| POST | `/api/factory` | `{"confirm":"ERASE"}` |
| POST | `/api/dump` | `{"channel":0..2,"enabled":true}` |
| POST | `/api/ota` | обновление, тело — сырой `firmware.bin`, не JSON и не multipart |

> Для OTA годится **только `firmware.bin`** — приложение. Объединённый
> `firmware_merged.bin` содержит загрузчик и таблицу разделов, и проверка
> образа его отклонит.
