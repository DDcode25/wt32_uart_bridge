# 07. Diagnostics

## Діагностика каналів

Те же счётчики, что на Status, собранные вместе. Разбор — в
[02. Status](02-status.md).

## Журналювання

**Детальний журнал** — уровень подробности. Включённый добавляет сообщения
уровня INFO; выключенный оставляет предупреждения и ошибки.

После отладки стоит выключать: журнал пишется в кольцевой буфер, и подробные
сообщения вытесняют оттуда всё остальное.

## Дамп трафіку

Побайтовый вывод трафика канала в журнал. **В NVS не сохраняется**: после
перезагрузки всегда выключен, чтобы забытый включённым не грузил лог.

Строки помечены направлением — на общем проводе это существенно, потому что
четыре разные вещи выглядят в hex одинаково:

| Метка | Что это |
|---|---|
| `UART RX` | пришло с провода |
| `UART TX` | отдано в провод |
| `UDP RX` | пришло из сети |
| `echo suppressed` | снято как собственное эхо |

Пример исправного транзита — `UDP RX` и `UART TX` совпадают байт в байт:

```
UART1_CRSF UDP RX  26B: ee 18 16 11 f4 61 2b a0 ...
UART1_CRSF UART TX 26B: ee 18 16 11 f4 61 2b a0 ...
UART1_CRSF UART RX 14B: c8 0c 14 11 11 64 b6 00 00 00 23 64 c8 16
```

Последняя строка — настоящий кадр link statistics со встречной стороны.

Дамп **прорежен**: не чаще одной строки в 100 мс на каждое направление. CRSF на
400000 бод забил бы кольцевой буфер за секунду. Всё пропущенное считается и
печатается в следующей строке — `[пропущено 25 порцій / 650 Б]`.

> На однопроводном канале в дамп попадают только **целые кадры**. Мусор, не
> сложившийся в кадр, увидеть так нельзя — для этого есть приём с RAW-режимом,
> см. [09. Как диагностировать](09-diagnostika.md).

## Журнал пристрою

Кольцевой буфер сообщений прошивки, тот же `GET /api/log`.

Он нужен потому, что **UART0 может быть отдан каналу данных**. У ESP32 три
UART-периферии, все три заняты каналами, а UART0 — ещё и консоль. Как только
канал забирает UART0, консоль замолкает: иначе строки журнала физически
подмешались бы в поток канала и уехали клиенту по сети.

Начало журнала — старт каналов, передача UART0, получение адреса — печатается
**до** перехвата, поэтому в терминале при первом включении оно видно, а в этом
буфере его нет.

## API пристрою

Список конечных точек. Полезные для скриптов:

| Точка | Что делает |
|---|---|
| `GET /api/status` | всё состояние в JSON |
| `GET /api/config` | текущая конфигурация |
| `POST /api/config` | записать конфигурацию целиком |
| `GET /api/log` | журнал |
| `POST /api/dump` | `{"channel":1,"enabled":true}` |
| `POST /api/reboot` | перезагрузка |
| `POST /api/ota` | обновление, тело — `firmware.bin` |
